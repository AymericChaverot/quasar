`qsr` is Quasar's command-line client: list applications, deploy them and wait for the outcome, follow their logs, and edit their environment, from a terminal or a pipeline. It talks to the [API](/reference/api/overview/) and needs Quasar v0.5.2 or later.

Its source, releases and install instructions are on [GitHub](https://github.com/AymericChaverot/quasar-cli).

## Sign in

Create a **personal token** in **Settings → Personal tokens**, then:

```bash
qsr login prod https://admin.your-domain.com
```

`qsr` asks for the token, checks it, and keeps it under the name `prod`. A personal token acts as your account, with your role, so a viewer can list and read but not deploy. Several servers each get a name of their own; `qsr context use <name>` switches between them, and `--context <name>` picks one for a single command.

## Everyday commands

| Command | Does |
| --- | --- |
| `qsr apps` | List applications and their state. |
| `qsr apps show blog` | One application, and why its last deploy failed if it did. |
| `qsr deploy blog` | Fetch the latest version, deploy it, and wait for the outcome. |
| `qsr start blog`, `stop`, `restart` | Start, stop or restart its containers. |
| `qsr logs blog -f` | Its recent logs, then new lines as they come. |
| `qsr env blog` | Its environment variables (an admin's personal token only). |
| `qsr env set blog DEBUG=1 --deploy` | Change a variable and redeploy with it. |
| `qsr apps create blog --git https://github.com/me/blog.git` | Create an application (also `--image`, `--compose` or `--local`) and deploy it. |
| `qsr apps delete blog` | Delete it, with its containers, files and data, once its name is typed back. |

An application is named by its id, its subdomain or its name. Every command takes `--json` for scripts.

## Deploy a folder from your machine

An application created with `--local` has no repository or image: it runs the folder you send it, built the way a repository is, with its compose file when it has one at its root and otherwise with its Dockerfile.

```bash
qsr apps create "My site" --local --port 8080
qsr deploy my-site ./site
```

`qsr deploy` packs the folder, leaving out `.git` and whatever its `.gitignore` and `.dockerignore` exclude, uploads it, and waits for the deploy like any other. Each upload replaces the previous one; **Redeploy** on the dashboard builds the last one again. An admin sets the largest upload accepted in **Settings → Folder uploads**, 200 MB compressed by default, and `qsr` refuses a larger folder before sending it.

Creating, deleting and deploying folders need Quasar v0.6.0 or later.

## In a pipeline

Skip `login` and give the address and a token through the environment:

```bash
QSR_URL=https://admin.your-domain.com QSR_TOKEN=${{ secrets.QUASAR_TOKEN }} qsr deploy blog
```

`qsr deploy` exits with an error when the deploy fails, so the pipeline fails with it. A [service token](/reference/api/overview/#service-tokens) works here, except for reading environments.
