## Dashboard

The dashboard's home page shows:

- **Server health**: live CPU, memory and disk usage. Each bar has a tick where its [alert](/server/notifications/#usage-alerts) fires, and turns amber in the 15 points below it. Next to the figure, an arrow gives the change since the same hour yesterday, in % for the CPU and in GB for the memory and the disk. Under the bar: the cores and the load, the swap, and when the disk will be full at its pace of the last week.
- **History**: CPU, memory and disk on one chart, over the last hour, 24 hours, 7 days or 30 days.
- **Applications**: every application with its status and what it uses.
- **System containers**: Traefik, the socket proxy and the dashboard itself. Click one for its resources and live logs; the dashboard's own log is described in [dashboard log](/server/dashboard-log/).

### History

The toggles under the chart turn each part of it on or off, and the choice is remembered:

| Toggle | Draws |
| --- | --- |
| **CPU**, **Memory**, **Disk** | The measurement, as an average over each point. |
| **Min / max** | The lowest and highest sample behind each point, as a band: a spike averaged away is still there. |
| **Alert thresholds** | A dashed line at each alert's level. |
| **Events** | A dashed line at each deployment, automatic restart and alert. Hover one for what it was. |

**Top consumers**, next to the window, opens the applications' memory or CPU stacked over the same window, and their ranking right now.

### Applications

**Resources**, next to the list's heading, chooses how it shows what each running application uses:

- **Bars**: CPU and memory against the whole server.
- **Columns**: CPU and memory, each after a line of its last 24 hours.
- **Hidden**: neither.

Metrics are sampled every minute and kept for 7 days, then one point per hour (average, minimum and maximum) for 30 days.

## System page

**System** describes the server itself:

- **Hardware**: processor, memory and disk capacity.
- **Environment**: operating system, drawn with its distribution's logo, and the Docker and Traefik versions. See [server updates](/server/updates/) and [updating Traefik](/getting-started/updating/#updating-traefik).
- **TLS certificates**, **Docker storage**, **Volumes**, **Application storage** and **Backups**, covered in their own pages.

## Logs

**Logs** in the navigation searches the stored output of every application. See [searching past logs](/applications/logs-history/#searching-past-logs).

## Audit log

**Audit** lists who did what, when, and from where: deployments, setting changes, file edits, sign-ins, station actions…

- Entries can't be edited, and only go as a whole: by age, or all at once. In **Settings** → **Logs & audit**, set how many days they are kept (0, the default, keeps them with no age limit, up to the newest 20,000), or **Empty the audit trail**. Emptying it leaves one entry behind: the purge itself, with who did it and from where.
- Use the search box to filter them. The number of matching entries is shown above the list.
- Entries come 50 at a time, newest first. Use the pager under the list, or type a page number into the current page's box.
- Actions triggered by a webhook or an API token are recorded under that name.
